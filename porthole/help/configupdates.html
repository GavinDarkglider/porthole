Configuration updates

When a package is updated, it never overwrites a configuration file you changed (one under CONFIG_PROTECT, most of /etc). It puts its new version next to yours, named ._cfg0000_<name>, and the choice is yours. On the command line that is etc-update or dispatch-conf; in Porthole it is Actions, Configuration Updates…. A file you never changed is replaced by the package itself and never shows up here.

Settled by themselves

After every update or install, Porthole settles the ones that need no decision, and the job's log says which, and which are left for you:

  • the new version is the same as yours (its copy is just removed),
  • only comments or blank lines differ (the new version is taken, with its new notes),
  • you never changed the version Porthole saw last time (the new version is taken),
  • the package didn't change it since then (yours is kept),
  • both you and the package changed it, in different places: the two are merged, the way a version control tool merges changes.

The last three need the version Porthole saw last time: each version you settle on is kept in /var/lib/porthole/config-archive, readable like the file itself. So the first update of a file after installing Porthole may ask you; later ones usually won't.

The ones for you

Each file left shows what happened, and two views:

  • Differences: your file against the new version (red is yours, green the new one).
  • Result to save: what Porthole suggests, which you can edit. For a file of settings (KEY="value" lines, like those in /etc/conf.d) it is the new file, with its new notes and new settings, and your values kept; the list above it says what changed. Where you and the package changed the same lines, both are shown between <<<<<<< and >>>>>>>: keep the lines you want and remove the markers before saving.

Then Keep mine, Use the new version or Save this result; each asks for the administrator password (unless Porthole is unlocked). A file only root can read can't be shown; you can still keep yours or take the new version.

etc-update -3 and -5 don't merge: they replace every file you changed with the package's new version, without asking.

Systems for other computers

For: at the top picks this computer or one of the systems Porthole builds. A system's health check, at the end of each build, settles its updates that need no decision and warns about the rest, so an image isn't made with old settings.

On the command line:

porthole-update-service config-updates list [--target NAME]
porthole-update-service config-updates auto [--target NAME]          (as root)
porthole-update-service config-updates apply --file /etc/... --choice keep|new|merged [--content FILE]
