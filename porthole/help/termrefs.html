Words used in Porthole and Gentoo

Architecture (arch)
The kind of processor a system is built for, such as amd64 or arm64.
Binary package, binhost
A package already built, downloaded instead of compiled; a binhost is a server that offers them. Portage uses one only if it was built with your USE flags. See Settings, Binary packages.
Build window
The hours in which approved updates may be built, when nobody is using the computer. See How updates run.
Ebuild
The script that tells Portage how to build one version of a package: where to get it, what it depends on, its USE flags and keywords.
Emerge
Portage's command for installing, updating and removing packages. Porthole runs it for you.
Keyword (stable, testing)
Whether a version is considered ready on an architecture: amd64 means stable, ~amd64 testing. Portage installs only stable versions unless you accept testing ones, for a package (package.accept_keywords) or for everything.
Licence group
A named set of licences, such as @FREE or @EULA, used to say which licences are acceptable. See Settings, System, Licences.
Live package (-9999)
A package built from the newest source in its upstream repository rather than a release. Porthole can rebuild live packages when upstream has new commits.
Mask
A version Portage won't install: because it is known to be broken or unsafe, not yet ready, or because you masked it (package.mask). A mask can be lifted (package.unmask), but there is usually a reason for it.
News item
A notice from Gentoo about something you may need to do. See News.
Package, atom
A package is named category/name, such as sys-process/htop. An atom is a package name with a version condition, such as >=sys-process/htop-3.5.
Plan
What Porthole worked out for an update or install: what is built, in which order, which setting changes are needed, and what is held back. See Updates.
Portage
Gentoo's package manager. Its settings are in /etc/portage: make.conf, the package.* files, repos.conf and more.
Preserved libraries
Old versions of libraries kept because programs still use them after an update. Those programs are rebuilt (@preserved-rebuild) so the old libraries can go; Porthole does this at the end of an update.
Profile
The base settings a system starts from: default USE flags, which packages make up the system, the init system. See Settings, System.
Repository (overlay)
A collection of ebuilds. Gentoo's own is gentoo, kept in /var/db/repos/gentoo; others (often called overlays) add packages. See Settings, Repositories.
Resolver, runner
The parts of Porthole that work out plans, and that carry them out as root. See About Porthole.
Set
A named group of packages, written with @: @world, @system, @preserved-rebuild, or your own.
Slot
Versions of a package in different slots can be installed side by side, such as two major versions of a compiler or library.
Sync
Bringing the repositories up to date. See Syncing.
Unlock
Typing the administrator password once for a while instead of for every change. See Unlock.
USE flag
A switch for an optional feature, such as bluetooth or pulseaudio. Set for everything (in make.conf, the profile, or Porthole's settings) or for single packages (package.use). Groups of flags for one subject, such as VIDEO_CARDS, are called USE_EXPAND variables.
World, world file
The packages you asked for yourself (@world), listed in /var/lib/portage/world. Updates keep them and what they need up to date; a package installed one-shot isn't added to it.
