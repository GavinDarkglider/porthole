Removing packages

Removing a package

Select the package and press Unmerge on the toolbar (or use its right-click menu, or Package, Unmerge Package). Removing needs administrator rights, so Porthole asks for the password (unless it is unlocked) and hands the removal to the runner, which does it in the background; the job window shows it.

In the Updates Available, Deprecated and Sets views, the packages you tick are removed together, as one job.

Removing a package doesn't check whether something else needs it. If another program stops working afterwards, reinstall what you removed.

Removing one version

If several versions are installed (in different slots) and you want to remove one, right-click it in the version table on the package's Summary tab and choose Unmerge this version. Advanced Emerge can do the same: choose unmerge and the version.

Removing what nothing needs any more

Removing a package leaves behind what was installed only because it needed it. Updates lists such packages after each check, under No longer needed, and removes only the ones you tick, after the update. After removing something, press Check now there to see what it left behind.

Packages from a repository you remove

When you remove a repository in Settings, Repositories, Porthole lists the packages installed from it and asks whether to keep them (they get no more updates) or remove them too.
